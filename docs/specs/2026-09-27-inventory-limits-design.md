# Larger inventories — design

Status: option chosen by the user, 2026-09-27 (agent M1 limits review);
written spec awaiting review.

## 1. Why (M1 limits spike, 2026-09-27)

Measured with the real agent on a Fedora 44 workstation: 3,613 RPM
packages give a 483 KB inventory (134 bytes per package), so the V1 limits
are reached at about **7,800 packages** (1 MiB document) and **10,000
packages** (fact list). Fedora offers 9,527 `texlive-*` packages alone, so
a workstation with the full TeX Live passes both. Today such a host fails
quietly:

- 7,800–10,000 packages: the agent's transport refuses to send an
  inventory over 1 MiB, the failure is retried every minute for ever, and
  the host never gets vulnerability matching.
- over 10,000 packages: `collect_packages` fails as a whole, so matching is
  lost and so are the `package.names` and `package.count` facts: every
  package rule on the host reports unavailable.

Every other V1 limit had ample headroom (strings: longest 45 of 4,096
bytes; process names 583 of 10,000; ports 36; scan 0.16 s of 300 s).

## 2. Decision (the user, option 1)

Separate, larger limits for inventories only; everything else keeps its V1
value.

| New V1 limit | Value | Applies to |
|---|---|---|
| `inventory_items` | 50,000 | packages in `InventoryReport` and `InventoryExport`; the package collector; the `package.names` fact list |
| `inventory_document_bytes` | 8 MiB (8,388,608) | one `InventoryReport` body (`POST /v1/inventory`) or `InventoryExport` file |

At 134 bytes per package, 50,000 packages are about 6.7 MB, inside 8 MiB.
All other documents (findings, heartbeats, rule bundles, finding exports)
stay at 1 MiB and every other fact list at 10,000.

Why `package.names` too: the rules over package facts must keep working on
the same hosts; CEL `in` on a sorted list is a binary search, and 50,000
names (about 1 MB) fit well inside `fact_input_bytes` (16 MiB).

## 3. Changes

**Protocol (first).** `ResourceLimits` table in `contracts-v1.md` gains the
two limits; `inventory-report` and `inventory-export` schemas raise
`packages.maxItems` to 50,000; the text says an inventory is bounded by
`inventory_document_bytes` instead of the 1 MiB document limit. Fixtures:
a valid report with 10,001 packages (generated by the validator tool, not
checked in at full size) and an invalid one with 50,001.

**Agent.**
- `ResourceLimits::V1` gains `inventory_items: 50_000` and
  `inventory_document_bytes: 8_388_608`; `InventoryReport` and
  `InventoryExport` validate against them.
- `collect_packages` caps at `inventory_items`; `package.names` may hold up
  to `inventory_items` names (the only fact list above `fact_list_items`).
- The transport allows a request body up to `inventory_document_bytes` for
  `/v1/inventory` only; every other request keeps `document_bytes`.
- **No retry loop:** an inventory the agent cannot send because it is over
  the limit, or that the platform refuses with a 4xx, is remembered by its
  digest; the agent logs once and does not resend until the inventory
  changes. Network errors and 5xx are still retried on the next tick.
- Export writes inventories up to `inventory_document_bytes`.

**Platform.**
- `platform-agent-server`: the body limit is per route: 8 MiB for
  `/v1/inventory` (declared `Content-Length` and read body), 1 MiB for
  everything else, as today.
- **Memory bound:** at most 4 inventory requests are handled at once
  (a separate semaphore); a fifth gets 503 and the agent retries on the next
  tick. Worst case 32 MiB of inventory bodies in flight.
- `openvibes-admin import`: a file up to 8 MiB is read; a `FindingExport`
  over 1 MiB is still refused, an `InventoryExport` up to 8 MiB accepted.
- Storage and matching handle 50,000 packages per host unchanged
  (`inventory::replace` sends column arrays; the scale runs covered 10,000
  hosts at ~390 packages, not one host at 50,000; a store test covers it).

## 4. Testing

- Protocol: schema limits at 50,000/50,001 packages.
- Agent: validation at the limits; `collect_packages` with a synthetic
  11,000-package dpkg status succeeds and `package.names` holds 11,000;
  transport refuses 8 MiB + 1 for `/v1/inventory` and 1 MiB + 1 elsewhere;
  a refused inventory is not resent until it changes (a mock platform
  counting requests).
- Platform: `/v1/inventory` accepts a 7 MB body and refuses 8 MiB + 1;
  `/v1/findings` still refuses 1 MiB + 1; the fifth concurrent inventory
  gets 503; `inventory::replace` stores 50,000 packages; admin import of a
  5 MB inventory export.
