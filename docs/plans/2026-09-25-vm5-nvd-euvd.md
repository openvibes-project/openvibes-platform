# VM5: NVD and EUVD Enrichment — Implementation Plan

> **For agentic workers:** superpowers:executing-plans (native). Steps use checkboxes.

**Goal:** Add CVSS, weakness types (CWE) and descriptions from NVD, and the
EU vulnerability database's exploited list, to the CVEs our advisories name.

**Spec:** `docs/specs/2026-09-25-vulnerability-management-design.md` §6, §9.

## Facts checked on 2026-09-25

- NVD API 2.0 `https://services.nvd.nist.gov/rest/json/cves/2.0`: 397,529
  CVEs; 2,107 changed in the last 24 h (9.3 MB per page of 2,000, about
  4.6 KB a CVE; log4j alone is 87 KB). `cveId=` takes one id;
  `lastModStartDate`/`lastModEndDate` windows are at most 120 days; pages
  of at most 2,000 with `startIndex`. Public limit 5 requests per 30 s, 50
  with an API key (`apiKey` header).
- A full NVD mirror would be about 1.8 GB to download and hundreds of MB to
  store; Fedora 44's 385 security advisories name only 944 distinct CVEs.
- EUVD `https://euvdservices.enisa.europa.eu/api/search?exploited=true`:
  1,735 exploited entries, at most 100 per page (`page=`), about 280 KB a
  page; each has `id` (EUVD-…), `aliases` (CVE ids among others,
  newline-separated) and `exploitedSince`. No ETag.

## Global Constraints

- **Light:** NVD data is kept only for CVEs our advisories name. New
  ones are fetched one by one (backfill, paced to the rate limit: 6 s
  between requests, 0.6 s with a key: first fill of Fedora 44 about 95 min,
  or 10 min with a key); every interval one incremental query by
  last-modified time updates them. CVEs NVD does not know are asked again
  after 7 days.
- The NVD work runs in its own task, so pacing never delays re-matching.
- The API key is optional, read from a file (`nvd_api_key_file`, not
  readable by others), never logged.
- EUVD's exploited list is kept whole (like KEV). Priority: exploited
  (KEV **or** EUVD) first, then EPSS percentile, then severity, then
  CVSS, then oldest.
- Migration 0011: NVD and EUVD columns on `cve_enrichment`;
  `feed_sources.cursor` (the NVD sync point).
- Offline: `feeds import FILE --source nvd|euvd` takes an API response
  saved to a file.

## Review Focus

- The CVSS kept is the newest version NVD scored (4.0, then 3.1, 3.0, 2), preferring NVD's own over a CNA's (Task 1 test).
- An incremental window older than 120 days is split, never refused (Task 3 test).
- A 403/429 from NVD stops the run and keeps the cursor, so nothing is skipped (Task 3 test).
- A CVE leaving EUVD's exploited list loses its mark (Task 2 test).
- A malformed page keeps stored data and is recorded (Tasks 2, 3 tests).
